# RFC-0001: Workspace Lifecycle

> Status: **Proposed**  
> Target: UnAI Core / Runtime / CLI  
> Author: UnAI Architecture Group  

---

## 1. Что это (What it is)
Стандартизированный жизненный цикл любого воркспейса (будь то built-in Web Workspace или маркетплейс-клиент вроде Discord) внутри рантайма UnAI. Это единый конечный автомат (State Machine), по которому живут все воркспейсы, что позволяет CLI (`unai workspace`), ядру и Notification/Status сервисам единообразно мониторить их состояние без разногласий.

## 2. Диаграмма состояний (State Machine)

```text
               ┌──────────┐
               │  Created │
               └────┬─────┘
                    │
                    ▼
               ┌──────────┐
               │Installing│
               └────┬─────┘
                    │
                    ▼
               ┌──────────┐
               │Registered│ (Манифест прочитан, в реестре ядра)
               └────┬─────┘
                    │
                    ▼
               ┌──────────┐
               │ Starting │
               └────┬─────┘
                    │
        ┌───────────┴───────────┐
        ▼                       ▼
   ┌──────────┐           ┌──────────┐
   │ Running  │           │Background│ (работает без UI/фоном)
   └────┬─────┘           └────┬─────┘
        │                      │
        └──────────┬───────────┘
                   │
                   ▼
               ┌──────────┐
               │ Stopping │
               └────┬─────┘
                   │
        ┌──────────┴───────────┐
        ▼                      ▼
   ┌──────────┐           ┌──────────┐
   │ Stopped  │           │  Failed  │ (крэш / ошибка инициализации)
   └──────────┘           └──────────┘
                            │
                            ▼
                      ┌──────────┐
                      │Uninstalling│
                      └──────────┘
```

## 3. Описание состояний (State Definitions)

1. **`Created`** — Воркспейс скачан клишкой или объявлен в системе, файлы на диске, но ядро о нём ещё ничего не знает.
2. **`Installing`** — Установка зависимостей воркспейса (если у него свой изолированный окружение/пакеты).
3. **`Registered`** — Манифест (`RuntimeManifest`) прочитан, возможности (Capabilities) проиндексированы Capability Resolver'ом, но процесс рантайма ещё не запущен.
4. **`Starting`** — Инициализация соединения, запуск фонового процесса/драйвера (например, запуск KasperBridge или подключение к Discord WebSocket).
5. **`Running`** — Активное рабочее состояние. Воркспейс обрабатывает вызовы шины (`call`), эмитит события (`emit`) и отвечает на пинги.
6. **`Background`** — Фоновый режим работы (активен без фокуса агента, продолжает собирать нотификации и держать соединение).
7. **`Stopping`** — Штатное завершение работы (отправка SIGTERM, закрытие сокетов, отписка от шины).
8. **`Stopped`** — Остановлен штатно. Ресурсы освобождены, но воркспейс остаётся в реестре (может быть перезапущен).
9. **`Failed`** — Аварийное падение (крэш, таймаут подключения, ошибка аутентификации). Передаёт событие на шину (`workspace.status.changed`), диагностируется через `unai doctor`.
10. **`Uninstalling`** — Удаление воркспейса из системы (`unai workspace remove <id>`), зачистка файлов.

## 4. Как это используется в экосистеме
- **`unai workspace ls`** — выводит таблицу со статусами (`Running`, `Failed`, `Stopped`).
- **Status Service** — подписывается на переходы состояния и обновляет статус агента (например, если воркспейс перешёл в `Failed`, Диром шлёт алярм).
- **`unai repair`** — автоматически перезапускает воркспейсы, застрявшие в `Failed`.
