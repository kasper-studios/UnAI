# RFC-0002: Tool Documentation & Discovery API

> Status: **Proposed**  
> Target: UnAI Core / Agent SDK / Protocol  
> Author: UnAI Architecture Group  

---

## 1. Что это (What it is)
Контракт токен-экономной документации инструментов (Tools). Чтобы агент не таскал в контексте 50 страниц сухих JSON-схем и описаний каждого метода всех воркспейсов, UnAI реализует концепцию **Lazy Discovery & Structured Tool Help**:
- В промпте агента живут только компактные сигнатуры и ссылки (например, `browser.click -> docs/tools/browser.md#click`).
- Агент при необходимости может «допросить» систему через встроенный мета-инструмент `unai.describe_tool` или `unai.help`, чтобы получить подробности, примеры и обработку крайних случаев («пуки-каки») для конкретного метода.

## 2. Архитектура контракта

### А. Компактный манифест в системном промпте
Когда воркспейс регистрируется в ядре, он передаёт не портянку текста, а структурированный реестр:
```json
{
  "workspace": "browser",
  "tools": [
    {
      "method": "browser.dom.click",
      "summary": "Click DOM element by CSS/ref.",
      "ref": "docs/tools/browser.md#dom-click"
    }
  ]
}
```

### Б. Мета-инструмент `unai.describe_tool`
Если агенту нужны детали реализации или примеры, он вызывает системный метод ядра:
```python
async def describe_tool(method: str) -> dict:
    """Вернуть полную документацию, примеры и гайд по обработке ошибок для метода."""
    # Возвращает содержимое соответствующего секции из docs/tools/<workspace>.md
```

## 3. Что это даёт
1. **Экономия контекста (Token Budget)**: системный промпт не забивается терабайтами описаний тулов.
2. **Единый источник правки**: документация хранится в `docs/tools/` и подтягивается динамически или собирается клишкой при установке воркспейса.
3. **Борьба с галлюцинациями**: агент всегда может обратиться к первоисточнику («чекнуть `docs/tools/browser.md` на строках 12–40»), если встретил неопределённость.
