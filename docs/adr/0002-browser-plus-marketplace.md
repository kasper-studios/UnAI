# ADR-0002: Built-in browser workspace + workspace marketplace

> Status: **Accepted** (2026-08-02).

## 1. Что это (What it is)
Платформа UnAI поставляется с **одним встроенным (built-in) воркспейсом — Web/Browser Workspace** (KasperBridge: Firefox + Chrome, аккаунт-песочница «Диром/Hermes»). Всё остальное — Discord, Telegram, GitHub, Vault, 2FA, … — **НЕ встроено в ядро**: это пакеты маркетплейса, которые агент (или оператор) ставит одной командой по мере надобности.

```text
UnAI Core (built-in)
├── Browser Workspace            # гарантированная часть платформы
└── Marketplace
    ├── discord      → unai workspace install discord
    ├── telegram     → unai workspace install telegram
    ├── github       → unai workspace install github
    └── …            (vault, 2fa, …)
```

## 2. Почему является (Why it exists)
1. **Браузер — фундаментальная среда**: это «рычаг» по-максимуму — страницы, вход, DOM, скриншоты. Без него платформенность теряется, поэтому он гарантирован (built-in), а не идёт через каталог.
2. **Ядро остаётся лёгким**: Discord и пр. — отдельные пакеты, которые ставятся только если нужны. Никакого раздувания из коробки.
3. **Маркетплейс масштабируется**: новая соцсеть = новый пакет, независимое обновление; ядро не трогаем.
4. **Агент сам решает состав**: ему нужен Discord — он ставит пакет и получает соответствующие тулы; иначе их нет.

## 3. Что НЕ входит (What is NOT included)
- **НЕ все воркспейсы встроены** — только браузер. Остальное через маркетплейс.
- **НЕ принудительная установка всего**: ядро не тянет все пакеты сразу.
- **НЕ маркетплейс-рантайм внутри ядра** — каталог/подпись/репозиторий — отдельный сервисный слой (вероятно, часть CLI/сервиса), а не микроядро.

## 4. Токен-экономный контракт тулов
Каждый воркспейс-пакет публикует тулы по строгому правилу:
- **Короткое описание** (в Scheme тула): что делает, краткий пример, без воды.
- **Полная инструкция** — отдельный Markdown-файл `docs/tools/<tool>.md`, на который описание просто ссылается: «в случае пуки-каки чекай docs/tools/snapshot.md строки 12–40».

Зачем:
- в рантайме LLM расходуется минимум токенов (не таскаем весь документ в каждый контекст);
- детальная инструкция всегда под рукойпо ссылке, если агенту она реально нужна.

## 5. Открытые вопросы
1. Формат маркетплейса: статичный именованный каталог (`unai-marketplace.json` локально) vs удалённый репозиторий.
2. Подпись/проверка целостности пакетов (доверие при agent-side установке).
3. Как пометить `built-in` в манифесте (`features.builtin: true`) без путаницы с остальными `features`.
4. Как агент получает каталог — `unai workspace search`?
