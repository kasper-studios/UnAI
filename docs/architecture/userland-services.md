# Userland Services (Non-Normative)

> **Важно**: Всё перечисленное ниже — **необязательные примеры** пользовательских сервисов, реализуемых поверх ядра. Они не являются частью микроядра и могут быть заменены, удалены или переписаны без изменения контракта ядра.

---

## Список Known Userland Services

| Сервис | Назначение | Примерные возможности |
| :--- | :--- | :--- |
| **Planner Service** | Распознавание интентов, разбиение задач на шаги, выбор узлов | `planner.plan`, `planner.resolve` |
| **Workspace Service** | Изолированные среды агентов (Identity, Vault, Memory, Calendar) | `workspace.identity`, `workspace.memory` |
| **Web Runtime** | Живое управление веб-страницами (KasperBridge / Tampermonkey; реализации: Firefox, Chrome, Electron, WebView) | `web.dom.*`, `web.cookies.*` |
| **Vault Service** | Шифрованное хранение секретов, токенов, SSH-ключей | `vault.get`, `vault.set` |
| **Mail Service** | Чтение почты, парсинг OTP, автоматическая верификация | `mail.read`, `mail.otp` |
| **Python Runtime** | Выполнение Python (в т.ч. на мобильных устройствах / планшете) | `python.execute` |
| **Discord Runtime** | Управление Discord-ботом Dirom (живые объекты `bot`) | `discord.send`, `discord.listen` |
| **Telegram Runtime** | Управление Telegram-ботом (живые объекты `tgbot`) | `telegram.send`, `telegram.listen` |
| **Docker Runtime** | Управление контейнерами и изолированным исполнением | `docker.run`, `docker.stop` |

---

## Почему существует (Why it exists)
Основная философия: **ядро остаётся тупым и минимальным**. Вся интеллектуальная и бизнес-логика (от планирования до парсинга почты) живёт в заменяемых сервисах поверх System Bus. Это позволяет проекту эволюционировать: завтра Planner может быть заменён на другую модель или алгоритм, не трогая ядро.

## Что НЕ входит (What is NOT included)
- **НЕ являются частью микроядра**: Эти сервисы подключаются к шине как внешние процессы.
- **НЕ являются финальным списком**: Это лишь стартовые примеры (non-normative).
