# Architecture RFC: Behavior Layer

## 1. Что это (What it is)
**Behavior (Поведение)** — это средний слой абстракции между API рантайма и выводимыми возможностями (Capabilities). Полная лестница абстракций системы:

```text
API          →  Конкретные методы рантайма
               (web.click(selector), web.query(selector), web.type(selector, text))

Behavior     →  Устойчивое описание того, что умеет рантайм
               ("Взаимодействовать с DOM", "Читать cookies", "Управлять вкладками")
               — без привязки к реализации

Capability   →  Составная возможность, выводимая из набора Behavior
               ("Пользоваться веб-сайтами")

Intent       →  Намерение агента
               ("Опубликовать видео на YouTube")
```

Ключевая идея: **Capability — это уже крупная сущность**, а Behavior точно описывает то, что умеет конкретный рантайм. Именно Behavior (а не Capability) привязан к рантайму.

## 2. Почему существует (Why it exists)
1. **Технологическая нейтральность имён**: Рантайм называется не «Browser Runtime», а **Web Runtime / DOM Runtime / Interactive Runtime** — потому что реализацией может быть Firefox, Chrome, Android WebView, Electron или любой другой движок. Имя не должно навязывать реализацию.
2. **Устойчивость к замене**: Если завтра Firefox заменится на Playwright-рантайм, Behavior («взаимодействовать с DOM») останется тем же — поменяются только API-методы под капотом.
3. **Разделение уровней мышления**: Планировщик мыслит Behavior и Capability, рантайм публикует API, ядро выводит связи. Никто не смешивает уровни.

## 3. Что НЕ входит (What is NOT included)
- **НЕ является Capability**: Capability находится выше по лестнице и может комбинировать несколько Behavior.
- **НЕ является API**: API — это конкретные методы с сигнатурами; Behavior — это семантическое описание.
- **НЕ содержит бизнес-логику сайтов**: Behavior «взаимодействовать с DOM» не знает про GitHub или Figma.
- **НЕ привязан к конкретному браузеру**: Firefox, Chrome, WebView, Electron — просто реализации одного и того же Web Runtime.

## 4. Открытые вопросы (Open Questions)
1. Кто вычисляет Behavior: сам рантайм объявляет свои Behavior при регистрации, или ядро выводит их из сигнатур API (инференс)?
2. Нужна ли таксономия Behavior (стандартный словарь), чтобы разные рантаймы описывали одинаковые возможности одинаковыми словами?
3. Как Behavior соотносятся с версионированием контрактов рантаймов (semver для Behavior-слоя)?
