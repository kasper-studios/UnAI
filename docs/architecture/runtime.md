# Architecture RFC: Runtime (Pluggable Execution Environment)

## 1. Что это (What it is)
**Runtime (Рантайм)** — это изолированная среда исполнения, предоставляющая набор методов API через System Bus. Рантайм является основной единицей расширяемости системы: браузер, Python, Docker, Discord-бот, Telegram-бот — всё это разные рантаймы, подключённые по одному и тому же контракту.

Каждый рантайм публикует свой манифест:

```json
{
  "runtime": "browser",
  "id": "kasper-bridge-firefox",
  "methods": [
    "browser.dom.query",
    "browser.dom.click",
    "browser.dom.type",
    "browser.cookies.get",
    "browser.tabs.list"
  ]
}
```

## 2. Почему существует (Why it exists)
1. **Универсальность контракта**: Любая новая среда исполнения (Android, iOS, игровой движок, умный дом) подключается за счёт публикации своих методов — без изменения ядра и без написания интеграций под конкретные сайты.
2. **Живые сессии**: В отличие от изолированных headless-браузеров, рантайм может быть привязан к реальной сессии пользователя (Firefox с авторизациями), что критично для работы с админками, веб-чатами и OAuth-защищёнными сервисами.
3. **Изоляция сбоев**: Крах одного рантайма не затрагивает остальные; ядро лишь обновляет статус его возможностей.

## 3. Что НЕ входит (What is NOT included)
- **НЕ содержит бизнес-логики конкретных сайтов**: Рантайм браузера не знает про GitHub или Figma — он умеет только DOM, cookies и вкладки.
- **НЕ является ядром**: Рантайм не управляет шиной, узлами или графом возможностей.
- **НЕ является обязательным компонентом**: Ядро работает даже при полном отсутствии рантаймов.

## 4. Открытые вопросы (Open Questions)
1. Как версионировать методы API рантаймов (semver контрактов, backward compatibility)?
2. Нужен ли стандарт для «горячего» обновления рантайма без потери состояния (например, обновление юзерскрипта Tampermonkey без перезагрузки вкладки)?
3. Как ограничивать ресурсы рантаймов (CPU, память, сеть) — на уровне рантайма или ядра?
