# Architecture RFC: System Bus (Messaging & Routing)

## 1. Что это (What it is)
**System Bus (Системная Шина)** — это транспортный слой ядра, обеспечивающий связь между узлами кластера и рантаймами. Шина поддерживает 5 примитивов взаимодействия:

1. **RPC (Request / Response)**: Асинхронный вызов метода (`browser.dom.click`) с получением результата.
2. **Commands**: Направленные команды изменения состояния (`vault.store_credential`).
3. **PubSub Events**: События системы без обратного адреса (`ACCOUNT_CREATED`, `TAB_NAVIGATED`).
4. **Data Streams**: Потоки данных с высокой частотой (DOM Mutation Stream, Video Stream, Terminal Output).
5. **System Signals**: Низкоуровневые сигналы ядра (`NODE_DISCONNECTED`, `RUNTIME_OOM`).

## 2. Почему существует (Why it exists)
В распределенной системе компоненты не должны знать о местоположении друг друга. `System Bus` скрывает сетевую топологию: планировщику неважно, вызывается ли метод локально в том же процессе, через WebSocket во вкладке браузера или через gRPC на удаленном VPS.

## 3. Что НЕ входит (What is NOT included)
- **НЕ содержит логики обработки сообщений**: Шина только передает и маршрутизирует пакеты.
- **НЕ является очередью с долгосрочным хранением**: Для хранения состояния используются сервисы верхнего уровня (`Memory Service`, `Vault Service`).
- **НЕ привязана к единому протоколу**: Шина может использовать WebSocket, NATS, gRPC или Unix Domain Sockets под капотом.

## 4. Открытые вопросы (Open Questions)
1. Какая максимальная задержка (latency budget) допустима для высокочастотных потоков событий браузера?
2. Требуется ли сквозное шифрование (E2EE) между узлами на уровне сообщений шины или достаточно TLS на уровне сетевых соединений?
