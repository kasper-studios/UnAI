# Architecture RFC: Pluggable Workspaces & Native Client Integrations

## 1. Что это (What it is)
**Workspace (Воркспейс)** — это автономная, модульная среда исполнения (runtime), которая подключается к микроядру через системную шину и регистрирует свои возможности (capabilities) и опциональные фичи. 

Браузер больше не является монолитной основой системы — это лишь **один из воркспейсов** (`Web Workspace`), наряду со специализированными нативными клиентами (например, `Discord Workspace`, `Telegram Workspace`), которые работают через прямые API/протоколы без эмуляции кликов и парсинга HTML.

---

## 2. Архитектура контракта Workspace

Каждый воркспейс объявляет манифест с поддержкой опциональных возможностей (feature flags). Ядро не требует обязательной реализации всего интерфейса — воркспейс может реализовывать только то, что ему нужно.

```json
{
  "id": "discord-workspace",
  "name": "Discord Native Workspace",
  "version": "1.0.0",
  "capabilities": {
    "notifications": true,
    "settings": true,
    "persistent": true,
    "background": true
  },
  "methods": [
    "discord.chats.list",
    "discord.messages.send",
    "discord.notifications.check",
    "discord.status.set"
  ]
}
```

### Опциональные возможности (Workspace Features):
1. **Notifications (`notifications: true`)** — возможность агрегировать непрочитанные сообщения и пинги в общую системную шину уведомлений (`check notify`).
2. **Persistent State (`persistent: true`)** — наличие локального состояния (токены, кэш сессий, БД).
3. **Background Tasks (`background: true`)** — фоновые воркеры (например, поллинг новых сообщений в Discord/Telegram в фоне).
4. **Settings (`settings: true`)** — конфигурационные параметры (например, выбор браузера, аккаунт, прокси).

## 3. Сценарии использования: browser (built-in) + marketplace-клиенты
Браузер — **единственный built-in воркспейс** (`ADR-0002`). Тулзы типа Discord/Telegram — маркетплейс-пакеты, ставятся по команде `unai workspace install <name>`.

### А. Маркетплейс-клиенты (Discord Workspace, Telegram Workspace)
* **Проблема:** Эмуляция кликов и скриншотов через браузер для соцсетей медленная и хрупкая.
* **Решение:** Нативный воркспейс-пакет (`unai workspace install discord`) подключается к Discord API / WebSocket шлюзу напрямую.
* **Результат:** Агент вызывает tool `launch discord-workspace`, получает список непрочитанных чатов и пингов без всякой мишуры, отправляет сообщения и обновляет статус Дирома в Discord (например, «смотрит личные сообщения» или «смотрит канал #general на сервере X»).

### Б. Изолированный браузерный воркспейс (Web Workspace)
* У пользователя два браузера: **Firefox** (основной, личный) и **Chrome** (полностью отдается агенту).
* В Chrome залогинен пустой аккаунт с именем **Диром** (Dirom) или **Hermes**.
* При первом запуске расширениеавтоматически сообщает ядру, из какого браузера оно какает, после чего Web Workspace использует его по умолчанию.
* Доступен аргумент командной строки для запуска без участия пользователя.

---

## 4. Единая система уведомлений (`check notify`)

Ядро предоставляет единую команду для агента:
* `check notify` — возвращает непрочитанные уведомления и пинги со **всех** активных воркспейсов.
* `check notify --workspace discord-workspace` — фильтрует уведомления по конкретному воркспейсу.

---

## 5. Что НЕ входит (Non-Goals)
- Ядро не управляет бизнес-логикой конкретного воркспейса.
- Воркспейсы не имеют права напрямую обращаться к внутренним структурам друг друга минуя System Bus.
- Отсутствие требования обязательной поддержки уведомлений или фона у каждого воркспейса.
