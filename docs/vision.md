# Vision & Philosophy — UnAI

## Что это
**UnAI** — это воркспейс-центричный рантайм для автономных ИИ-агентов. Проект исследует переход от модели «LLM + монолитные MCP-тулы» к модели «LLM + набор подключаемых воркспейсов поверх общего микроядра и событийной шины».

Браузер — не платформа, а один из воркспейсов. Нативный клиент (Discord, Telegram) — такой же воркспейс, только без эмуляции кликов по HTML: он отдаёт агенту живые, структурированные данные напрямую.

## Почему существует
1. **Предел роста монолитных интеграций**: Делать отдельный MCP под каждую соцсеть/майку — комбинаторный взрыв неиспользуемого кода. Воркспейс-слой с общим манифестом и шиной решает это одним контрактом.
2. **Нативность важнее эмуляции**: Агент должен срать в инструмент (`launch discord-workspace`) и получать непрочитанные чаты/пинги нативной информацией, а не парсить скриншоты и DOM сайта Discord через клики.
3. **Не опрашивай — подпишись**: Уведомления, статус Дирома, логи, метрики — всё это простые подписчики одной событийной шины. Никто не поллит.
4. **Живые сессии какуна**: Браузер с готовыми куками/авторизациями (Chrome-песочница под «Диром/Hermes», а Firefox остаётся личным) уже открыт — не надо проходить OAuth/2FA заново.
5. **Распределённость изначально**: ноутбук, планшет, VPS, вкладки — система задумана распределённой на уровне ядерной шины.

## Что НЕ входит
- **НЕ монолит**: ядро не содержит логики всех воркспейсов; воркспейсы не ходят друг в друга мимо шины.
- **НЕ требует полный интерфейс**: воркспейс может поддерживать `notifications`/`persistent`/`background`/`settings` — или ни одно; ядро никогда не требует всего.
- **НЕ привязан к одному языку**: Runtime и воркспейсы — Python; CLI — Rust как *текущая* реализация (не вечное обязательство). Слои развязаны.
- **НЕ «очередная ОС»**: это рантайм-платформа, а не замена Linux/Docker/Kubernetes/браузеров.

## Открытые вопросы
1. Транспорт системной шины: UDS vs WebSocket vs gRPC vs NATS.
2. Как безопасно шарить OAuth-токены между воркспейсами и будущим Vault.
3. Оверхед сетевого слоя при частых мелких событиях.
4. Human-in-the-loop надёжность при опасных действиях агента в распределённой среде.
